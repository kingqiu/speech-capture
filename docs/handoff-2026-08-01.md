## 2. 已解决的问题

1. 真实 ASR 返回零时长/单字时间戳 → 已按停顿、长度、句末标点合并为可读段落；
2. 强制对齐器 int16 输入导致时间退化 → 已改为 float32；
3. 对齐词时间越界 → 已夹紧到段长；
4. 稳定段只能追加、不能在中间补缺口 → 新增
   `commit_gap_retranscription_segment` 中间插入；
5. VAD 缺口与对齐缺口轻微错位 → 改为以当前对齐报告的未覆盖范围为准；
6. 部分缺口与已有段冲突导致整任务中断 → 冲突缺口记为失败并继续；
7. 100MB WAV 上传需要分块 → 驱动脚本已支持 64MB 分块和幂等续跑，已包含在
   `9d9f164`；
8. 经复核的 `inaudible` 时间轴无法继续后续阶段 → 允许保持
   `transcript_complete = false` 的 partial 语义进入说话人识别，但真实 `failed`
   仍阻断；
9. 结构化输出校验异常未走降级 → 统一安全降级为 `generic + 空结论`，不接受
   非法或无证据结论。
10. `note.md` 只有 Meta 信息 → Ollama 改为严格 JSON Schema，分批失败互不影响；
    支持对 `processed` 作业安全重做结构化和原子替换产物；最终笔记以有证据的
    一分钟总览、关键信息、行动项和分歧为主体，极短遗漏仅做压缩说明。
11. 参考软件的纪要明显优于“发现项列表” → 增加跨批次全文综合，生成连贯摘要、
    核心结论、5–8 个主题、决定、待办、风险、未决问题和时间章节；每项继续绑定
    原文证据，不以无证据长文替代逐字稿。
12. 证据块号不可跨文件点击 → 改为 Obsidian `[[transcript#^block-id|时间]]` 链接。
13. 原始 ASR 无标点且混入极短外语幻觉 → 新增忠实校订层，原文保存在
    `speech-record.json` 的 `raw_text`，展示稿使用校订 `text`；非语音及明确的微小
    幻觉不进入 `transcript.md`。
14. 全量重跑成本过高 → 新增 `--document-only` 和 `--transcript-edits-only`，分别
    支持只重做全文综合、只拆小重试失败校订批次。
15. 校订后逐字稿没有反哺 Note → 校订现在先于分类与提炼完成，分批提取和全文综合
    统一读取校订文本；全文综合接收全部有效分段，而不是只接收 findings 引用的片段。
16. 固定“5–8 条重点”导致凑数和错判 → 改为按会议目的、参与方、明确结论、跨发言者
    回应、业务影响排序；核心结论和正文数量都由证据决定，章节导航由正文证据自动派生。
17. 缺少场景模板 → 提示词移入版本化的 `note_prompt_profiles.py`，为会议、访谈、课程、
    演讲、语音备忘和通用记录分别定义提炼标准；当前 prompt 版本为 `2026-08-02.8`，已验收
    会议主体最初由 `2026-08-01.19` 生成。
18. 多人会议缺少各方观点 → 新增 `speaker_summaries`；按发言量识别实质参与者，主体
    纪要遗漏时由 8B 只对缺失者做短补全，并要求至少引用一段本人发言。
19. 事实与性能门禁 → 负责人和期限只有在引用原文中能直接找到时才保留，否则自动留空；
    决定、待办、风险和未决问题不得复制同一句；最终证据使用短别名生成后还原为真实
    segment ID。14B 只负责一次主体全文综合，分类和分批初筛改由 8B 执行，校订批次从
    2400 字扩大到 4800 字。最终真实 document-only 运行约 7–8 分钟（含缺失发言者补全），
    首轮旧配置 20 分钟超时。
20. 同一议题前后观点被并列 → schema `1.3.0` 新增 `discussion_threads`，单独记录最初
    建议、后续修正、当前方向和 confirmed/tentative/open 状态；证据按时间校验，普通补充
    说明和重复脉络不会为了凑数进入该章节。
21. 早期提议被误写成决定或核心结论 → 决定必须引用含明确确认措辞的原文；没有通过
    门禁的决定降级，摘要中的无证据确定性句子删除，证据早于首次修正的相关 highlight
    不再占据核心结论，但仍保留在议题历史中。
22. 新增大字段导致 14B JSON 不稳定且完整重写过慢 → 主体纪要、多人补全、讨论演变和
    决定核对分离；旧主体可以只升级新增结构，确定性规则更新无需重新调用模型。
23. 讨论演变证据遗漏后段专有名词 → 从完整逐字稿补入更晚的同议题证据，并保留直接
    证据中的大写专有缩写；真实样例当前方向已明确显示 APS。
24. 音频提交时无法提供背景 → Worker 新增每任务可选、自由文本、多行多段的
    `recording_context`；支持创建时读取、按 revision 保存、替换和清除。
25. 背景可能污染事实 → 所有模型提示把它标记为“不可信参考而非证据”；结构化结果仍须
    引用逐字稿，事件只保存 supplied 状态和哈希；speech-record 记录应用来源但不把背景
    正文写成决定、待办或事实。
26. 修改背景后只能耗时全量重跑 → 新增 `--context-corrections-only`，对明确确认的专名
    做有界派生文本纠正；一般背景变化可走 `--document-only` 重新阅读完整校订稿，需要连
    逐字稿一起重做时才使用 `--force`。三条路径都不覆盖原始 ASR。
27. 项目所有者已明确确认 generation `19` 的 `note.md` 输出质量很高；该版本正式成为
    后续会议、访谈、课程/演讲、语音备忘/个人笔记和通用内容的 V1 质量参照。参照的是
    清晰度、完整性、准确性和证据可追溯性，不是统一套用会议模板。
