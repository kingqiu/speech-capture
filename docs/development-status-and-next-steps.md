## 2. 一句话现状

Speech Capture 已经从“产品构想”推进到一个具备持久化基础的本地 Worker 后端：

- 已能安全接收并校验大音频；
- 已能把音频确定性地标准化和切块；
- 已能调用本机的 MLX Qwen3-ASR 模型逐块转写；
- 已能保存不可变的原始模型结果和逐步出现的稳定文字；
- 已能在进程中断或电脑重启后保留进度并继续；
- 已有磁盘、内存和单任务调度保护；
- 已验证本机真实运行 Qwen3-ASR 1.7B；

因此，当前成果是“可靠的转写后端骨架和单块 ASR 执行链路”，还不是可以安装使用的完整插件。

## 3. 已经确定的产品边界

### 3.1 核心目标

**[设计已确定]**

首个个人版本必须同时满足两个最重要的质量目标：

1. **原始内容尽可能完整保存**
   - 原音频不被修改；
   - 音频中所有能够解码的时间范围都必须有明确处理结果；
   - 不能因为模型返回空内容、出错或重启而静默丢失一段音频；
   - 原始转写证据必须独立保存，不能只留下总结。

2. **提炼出的信息有效、可追溯**
   - 重要结论、行动项、决定和事实应能回到对应的文字证据；
   - 总结不能把推测写成事实；
   - 不确定、分歧和听不清的内容必须保留；
   - 结构化笔记要便于人阅读，也要便于未来 Agent 使用。

### 3.2 本地优先

**[设计已确定]**

- 默认使用用户自己拥有的 Apple Silicon Mac 上的模型处理。
- 云端 API 只作为将来的可选容错能力。
- 云端能力默认关闭，不得在用户不知情时上传音频或文字。
- Worker 协议不绑定某一家模型供应商，未来可以增加其他本地或云端后端。

### 3.3 远程使用方式

**[设计已确定]**

- 外出笔记本上的 Obsidian 插件可以把任务提交给家里的 Mac Worker。
- 处理发生在家里的 Mac，不需要远程控制家里电脑的图形界面。
- 上传完成后，即使外出笔记本关闭 Obsidian或断网，家里的 Worker 仍应继续处理。
- 重新连接后，插件从持久化快照恢复进度和已经完成的文字。
- Tailscale 是推荐的安全连接方式，但不能写死为唯一方案。
- Google Drive、iCloud、Dropbox、Obsidian Sync 等只负责 Vault 或文件同步，不承担任务协议。
- 用户更换同步方案时，插件和 Worker 的核心处理链路不应受影响。

### 3.4 电脑重启和登录边界

**[设计已确定]**

- 普通 Worker 服务重启后不应要求重新配对。
- 配对凭据应长期保存，并支持用户主动撤销。
- 后台服务应尽可能通过 macOS 系统服务自动启动。
- 如果磁盘加密要求用户先解锁系统盘，这是操作系统的安全边界，应用无法安全绕过。
- “无需图形界面”可以实现；“加密磁盘完全未解锁时仍访问用户数据”不能作为承诺。

### 3.5 多说话人内容

**[设计已确定，代码待开发]**

- 默认自动判断内容类型。
- 会议、访谈和其他多用户发言必须区分说话人。
- 初始结果可以使用“说话人 1、说话人 2”等匿名标签。
- 用户后续可把匿名标签改成真实姓名。
- 说话人识别失败时，不得丢弃已经完成的文字；应降级为“说话人未确定”并提示复核。

### 3.6 处理完成与发布到 Vault

**[设计已确定]**

- `processed` 表示 Worker 已完成处理并形成可校验的产物。
- `published` 表示产物已经成功、完整地写入当前 Obsidian Vault。
- 两者不能混为一谈。
- 远程处理完成时，如果家里 Mac 上的 Vault 同步副本可用，可以由 Worker 或获得发布租约的客户端发布。
- 如果发布失败，处理结果必须仍保留在 Worker 中，之后可以重试。

### 3.7 输出目录和日期

**[设计已确定]**

- 默认输出根目录为 Vault 相对路径 `Work/Speech Notes/`，并允许配置。
- 不把任何一台电脑上的绝对路径写入协议或笔记。
- 录音日期优先级：
  1. 用户明确指定；
  2. 可靠的媒体元数据；
  3. 可识别的文件名日期；
  4. 文件创建时间仅作为建议；
  5. 都不可靠时进入 `Undated`，等待用户确认。
- 文件上传或处理当天的日期不能自动冒充录音发生日期。

### 3.8 人工内容保护

**[设计已确定]**

- 生成内容与用户手写内容分区保存。
- `我的补充` 属于用户内容，重新总结或重新生成时不能覆盖。
- 说话人命名、转写纠正、录音日期纠正和总结重生成都要可追踪、可撤销。

### 3.9 暂缓的功能

**[后续扩展]**

- 访谈内容的深层意图识别。
- Windows 和 Linux Worker。
- 移动端直接提交。
- 可选云端 ASR、说话人识别或总结供应商。
- 翻译产物。
- 跨笔记知识整合和更复杂的 Agent 工作流。

访谈意图识别已明确记录为后续扩展，首个个人版本先不实现。

## 5. 已完成的模型验证

### 5.1 本地 ASR 模型

**[已实现并验证]**

已经在目标 Mac 上安装并运行：

- `mlx-qwen3-asr==0.3.5`
- 准确模式：`Qwen/Qwen3-ASR-1.7B`
- 速度模式：`Qwen/Qwen3-ASR-0.6B`
- 时间戳对齐：`Qwen/Qwen3-ForcedAligner-0.6B`

当前策略：

- 1.7B 作为默认“准确优先”配置；
- 0.6B 作为“速度和资源优先”配置；
- 后续在真实录音上继续比较两种配置。

### 5.2 合成双语基准

**[已实现并验证]**

已完成约 47.987 秒的中英混合合成音频基准：

| 配置 | 总耗时 | 实时系数 | 峰值进程内存 | 字符错误率 |
| --- | ---: | ---: | ---: | ---: |
| Qwen3-ASR 1.7B + 对齐器 | 29.62 秒 | 0.617 | 5.75 GB | 0.00% |
| Qwen3-ASR 0.6B + 对齐器 | 11.76 秒 | 0.245 | 3.53 GB | 1.05% |

两种配置均做到：

- 完整覆盖合成音频的解码时间线；
- 每个块都有结束原因；
- 没有检测到生成截断；
- 时间戳单调且在音频范围内；
- 保留中文—英文—中文切换。

### 5.3 Worker 中的真实模型执行

**[已实现并验证]**

Worker 的持久化执行链路已经真实调用 1.7B 模型两次，使用本地生成的中文测试语音：

> 这是语音捕捉插件的本地模型测试。我们需要完整保存每一段录音，并且生成可以核对的文字。

验证结果：

- 模型成功转写；
- 原始模型结果先写入私有、带校验和的文件；
- 随后才提交为插件可见的稳定文字；
- 处理进度达到完整音频时长；
- 作业进入后续对齐阶段；
- 重放路径不会重复调用模型。

## 6. 已完成的 Worker 后端能力

### 6.1 持久化作业状态机

**[已实现并验证]**

- 已定义严格、白名单式的作业状态转换。
- 每次状态变化都会增加版本号。
- 每个版本只有一条追加式事件。
- 非法跳转不会修改作业。
- 调用方需要提供自己看到的版本号，防止并发覆盖。
- 重复创建同一任务可通过幂等键返回原任务。
- 同一幂等键对应不同请求会明确报冲突。
- 阶段检查点独立保存，可跨暂停、失败、取消和重启保留。

代表性成功流程：

`created → uploading → verifying → queued → preprocessing → transcribing → aligning → diarizing/structuring → quality_check → processed → publishing → published`

同时支持：

- `paused`
- `waiting_user`
- `partial`
- `failed`
- `cancelled`

### 6.2 SQLite 持久化

**[已实现并验证]**

- 当前数据库 schema 版本：7。
- 当前包含 13 张核心表：
  - jobs
  - job_events
  - job_checkpoints
  - uploads
  - upload_parts
  - transcript_segments
  - provisional_transcripts
  - job_progress
  - job_updates
  - asr_attempts
  - corrections
  - publication_leases
  - publication_receipts
- 启用 SQLite WAL。
- 启用外键约束。
- 使用 FULL 同步持久化。
- 配置忙等待超时。
- 关键写入使用即时事务。
- 数据库文件和应用数据目录使用限制性权限。

### 6.3 重启恢复

**[已实现并验证]**

- Worker 异常停止后，正在处理的状态会恢复到可安全继续的队列状态。
- 正在发布的任务恢复为 `processed`，避免把未完成的发布误报为成功。
- 已经提交的转写段、临时尾部、进度、上传部件、原始 ASR 尝试和检查点都会保留。
- 已完成的模型尝试可以从原始证据重放，不需要再次推理。

### 6.4 资源安全检查

**[已实现并验证]**

磁盘策略：

- 必须保留“20 GiB”和“磁盘容量 10%”中的较大值。
- 在开始处理前估算源文件、标准化 PCM 和工作产物所需空间。
- 磁盘接近危险状态时给出警告或阻止处理。
- 系统只提示用户手工清理，不自动删除文件。

内存策略：

- 准确模式最低建议 16 GB；
- 速度模式最低建议 8 GB；
- 检查可用内存、内存压力和交换空间风险；
- 警告状态可以按规则继续；
- 严重状态在下一个 ASR 块开始前安全暂停；
- 已经完成的文字和模型结果不会丢失。

调度策略：

- 同一 Worker 同时只运行一个重型任务；
- 选择最早的、已经完整验证的队列任务；
- 每次开始调度都会持久化当时的资源检查结果；
- 未绑定可靠音频源的开发任务不会被正式调度。

### 6.5 大文件可恢复上传

**[已实现并验证]**

- 默认上传块大小为 8 MiB。
- 允许配置到最高 64 MiB。
- 一个上传最多 10,000 个块。
- 块编号从 1 开始。
- 支持乱序上传。
- 每块都校验精确字节数和 SHA-256。
- 相同内容重复上传是幂等操作。
- 同一块号出现不同内容会明确报冲突。
- 可以查询缺失块列表并续传。
- 最终组装时会重新校验所有已保存块。
- 校验总字节数和整个文件的 SHA-256。
- 使用 FFprobe 验证文件确实包含正时长音频流。
- 音频验证失败时不会创建可调度任务。
- 验证过程重启后可回到上传状态，已经收到的块仍保留。
- 文件使用私有目录、原子替换、同步写入和路径边界保护。
- 已防范符号链接和路径穿越。

### 6.6 渐进文字和重连快照

**[已实现并验证]**

稳定文字段支持四种明确结果：

- `transcribed`：成功转写；
- `inaudible`：无法可靠听清；
- `non_speech`：确认是非语音；
- `failed`：该范围处理失败。

当前约束：

- 稳定段按时间顺序提交；
- 不允许互相重叠；
- 不允许超出源音频范围；
- 相同提交键重复提交是幂等的；
- 相同提交键内容变化会报冲突；
- 后续时间对齐或说话人标注只能更新元数据，不能静默改写稳定文字；
- 每个作业最多有一个明确标记为“不稳定”的临时尾部；
- 临时尾部有独立版本保护；
- 进入对齐前必须清除或提交临时尾部。

插件未来重连时可获得：

- 作业当前状态；
- 当前阶段；
- 已处理时长和总时长；
- 阶段进度；
- 已耗时和可选剩余时间；
- 说话人识别状态；
- 稳定文字分页；
- 当前临时尾部；
- 资源检查报告；
- 后续更新游标。

边界保护：

- 每页最多 500 个文字段；
- 更新事件每页最多 1,000 条；
- 普通状态事件和更新事件不包含文字正文；
- 文字正文只通过受控快照接口返回。

### 6.7 确定性的音频标准化和切块

**[已实现并验证]**

- 已验证的源音频会被转换为私有的 16 kHz、单声道、16-bit PCM WAV。
- 转换副本移除不需要的元数据。
- 用户原始音频保持不变。
- 标准化文件有 SHA-256 和持久化计划。
- 标准化音频时长与媒体验证时长的差异不能超过 250 ms 或 1% 中的较大值。
- 如果标准化副本损坏，Worker 会从已验证源文件确定性重建。

切块策略：

- 默认每块最长 30 秒；
- 尾块最短目标 5 秒；
- 在边界前最多回看 3 秒；
- 使用 100 ms 能量窗口寻找较自然的切点；
- 所有边界以 PCM 帧为准；
- 块之间不重叠、不留空隙；
- 最后一块精确结束在最后一帧。

### 6.8 可恢复的本地 ASR 执行

**[已实现并验证]**

- 已有 `MlxQwenAsrEngine` 真实本地模型适配器。
- 模型按需要延迟加载。
- 每次后端命令执行一个持久化音频块。
- 每个块开始前重新做资源检查。
- 原始模型 JSON 先原子写入私有文件并计算校验和。
- 原始证据落盘后，文字才会变成稳定可见段。
- 尝试状态包括：
  - succeeded
  - rejected
  - failed
- 尝试编号从 1 开始且不能跳号。
- 尝试键和证据不可变。
- 数据库和普通事件只保存安全元数据，不暴露原始文字或异常消息。
- 校验模型输出是否覆盖当前块、是否截断、是否有结束原因、文字是否为空、时间戳是否单调且在范围内。
- 成功结果使用确定性提交键写成稳定段。
- 如果在原始结果落盘后崩溃，恢复时从该结果重放，不第二次调用模型。
- 被拒绝的模型输出可以重试。
- 模型异常只记录安全的异常类型，不保存可能含私人内容的异常消息。
- 默认最多尝试 3 次。
- 重试耗尽后把该时间范围明确记录为 `failed`，作业进入 `partial`，不会静默跳过。
- 对容器时长与 PCM 时长的毫秒级舍入差异已有安全夹紧处理。
- 已支持一次调用跑完所有剩余 ASR 块，可设置单次批次块数上限；
- 批次中断后可安全续跑，已经完成的块只重放证据，不会重复调用模型。

### 6.10 整篇对齐和完整性退出门

**[已实现并验证]**

转写块全部落盘后，Worker 现在会生成一份持久化的
`transcript_alignment_report`，而不是因为最后一个模型调用成功就直接进入
说话人识别。

报告分别验证：

- 每个标准化音频块都有匹配的成功原始 ASR 尝试；
- 每个块都有持久化的 materialization 检查点；
- 检查点引用的稳定文字段仍然存在；
- 原始模型结果文件仍能通过 SHA-256；
- 每个已转写段使用已对齐时间，而不是估算时间；
- 稳定结果在整条源时间线上不重叠；
- 是否存在未覆盖范围；
- 是否存在 `inaudible` 或 `failed` 范围；
- 当前任务是否真的可以进入说话人识别。

报告只包含：

- 安全的状态布尔值；
- 分段和音频块数量；
- 各结果类型的数量和总时长；
- 未覆盖的起止时间；
- 稳定问题代码。

报告不包含文字正文。普通事件和诊断输出仍不会泄露转写内容。

当前行为：

- 原始证据、对齐、时间线和文字完整性全部通过时，任务进入 `diarizing`；
- 存在估算时间戳时，任务保留在 `aligning`；
- 存在未覆盖范围时，任务保留在 `aligning` 并列出精确范围；
- 原始尝试或 materialization 证据缺失时，任务不能继续；
- 已完成的验收跨 Worker 重启保持幂等，不重复调用模型，也不重复转换状态。

目前该验收门能够准确识别缺口；下一节的 PCM 分析只证明最保守的确定性
静音，不会把可听但不确定的内容猜成非语音。

### 6.11 未覆盖范围的保守 PCM 证据

**[已实现并验证]**

Worker 现在可以通过 `analyze-gaps` 读取最新
`transcript_alignment_report` 中的精确未覆盖范围，并在已校验的标准化
16 kHz 单声道 PCM 上生成持久化的 `gap_audio_evidence`。

每段证据记录：

- 源时间线和 PCM 帧起止位置；
- 时长、峰值、RMS、非零采样比例和安静窗口比例；
- `definite_silence` 或 `unresolved`；
- 稳定原因码；
- 来源对齐报告的 generation 和 payload SHA-256；
- 标准化音频 SHA-256。

默认只有不少于 100 ms、并且所有采样峰值都不超过近数字静音阈值的范围
才会标成 `definite_silence`。以下情况全部继续保留为 `unresolved`：

- 短于最小静音时长；
- 存在明显可听 PCM；
- PCM 范围不可用；
- 任何无法仅靠幅度安全判断的内容。

报告不含文字正文、文件名或绝对路径。同一份对齐报告和同一标准化音频重复
分析时保持幂等；对齐报告发生变化后，新证据会记录新的来源 generation 和
SHA-256。

`analyze-gaps` 只生成可审计证据，不自动写入 `non_speech` 稳定段，也不改变
作业状态。下一节的独立命令负责使用固定保守策略完成安全落盘。

### 6.12 确定性静音的稳定时间线落盘

**[已实现并验证]**

Worker 现在可以通过 `materialize-silence` 重新运行固定默认策略，并把当前
`definite_silence` 写成：

- outcome：`non_speech`；
- timing status：`aligned`；
- 无文字正文；
- 无语言、置信度或说话人归属。

落盘前会再次验证：

- Gap checkpoint 的 generation 和 SHA-256 仍是当前值；
- Gap checkpoint 仍绑定当前整篇对齐报告；
- 策略固定为 20 ms 窗口、至少 100 ms、峰值阈值 8；
- 精确范围仍标为 `definite_silence`；
- PCM 帧数、峰值、安静窗口比例和原因码一致；
- 源时间范围完整映射到 PCM，不能用被文件尾部截断的部分采样下结论；
- 范围不与任何稳定段重叠。

自定义阈值只用于诊断，不能授权稳定时间线变更。补写可以发生在已有文字段
之前或中间，但不会改写已有 segment ID、sequence cursor 或文字正文。每个
补写范围都有独立私有 checkpoint，绑定：

- Gap 报告；
- 来源对齐报告；
- 标准化音频 SHA-256；
- PCM 聚合证据；
- 新增的稳定 segment ID 和 commit key。

命令完成后立即重新运行整篇对齐，使剩余 `unresolved` 范围和当前作业阶段
保持最新。插入稳定段后即使在证据 checkpoint 或对齐刷新之前崩溃，下一次
调用也会使用相同 commit key 幂等修复。

### 6.13 显式人工复核的未决范围落盘

**[已实现并验证]**

Worker 现在可以通过 `review-gap` 把一个经过人工试听的、完整且仍为当前值的
未决范围写成：

- `non_speech + aligned`；或
- `inaudible + aligned`。

命令只接收不透明的 `review_key`、精确起止时间和结果类型，不记录复核者
身份，也不接收自由文本备注。落盘前会验证：

- 范围在当前 `transcript_alignment_report` 中完整出现且只出现一次；
- 复核证据绑定当前对齐报告 generation 和 payload SHA-256；
- 复核 key 从未绑定到其他范围或其他结果；
- 范围不与现有稳定段重叠；
- 结果只能是 `non_speech` 或 `inaudible`。

每次复核都有独立的证据和 materialization checkpoint。相同请求重复执行会
返回原稳定段；在稳定段写入后、checkpoint 或对齐刷新前中断，也能幂等修复。
写入后立即刷新整篇对齐。`inaudible` 会解释该段时间线，但仍保持
`transcript_complete = false`，不会把部分结果伪装成完整结果。

这是“明确人工证据”通道，不是自动分类器。空 ASR、音量或可听 PCM 本身仍
不能自动区分语音、音乐、噪声和听不清内容。

### 6.14 估算时间戳的受控强制对齐回退

**[已实现并验证]**

Worker 现在可以通过 `force-align-next` 处理当前对齐报告中的下一个
`UNALIGNED_TRANSCRIBED_SEGMENT`。每次只处理一个稳定段，并保证：

- 不重新转写，不改写文字；
- 不改变 segment ID、commit key、语言、置信度或说话人字段；
- 只把原范围的标准化 PCM 和现有稳定文字交给
  `Qwen/Qwen3-ForcedAligner-0.6B`；
- 模型工作前重新检查磁盘和内存边界；
- 无语言元数据时不猜测分词方式；
- 词单元必须完整对应稳定文字，且时间有限、单调、不重叠、不越界；
- 只有首词开始到末词结束的外边界会写回稳定段。

词级原始结果先以 `0600` 权限原子写入私有文件并计算 SHA-256，然后保存安全
checkpoint。Checkpoint 绑定：

- 强制对齐前的整篇报告 generation 和 payload SHA-256；
- segment ID、revision、原范围和文字 SHA-256；
- 标准化音频 SHA-256、采样率和 PCM 帧范围；
- 模型 ID、词数、对齐后外边界和原始证据 SHA-256。

如果证据落盘后、segment 元数据更新前中断，下一次调用会直接重放证据，不
再次调用模型。整篇退出门会在每次验收时重新读取并验证私有文件；仅手工把
状态改成 `aligned`、文件缺失、内容不完整或校验和变化，都会产生
`MISSING_FORCED_ALIGNMENT_EVIDENCE` 并阻止进入 `diarizing`。

强制对齐收紧外边界后新出现的首尾静音仍会作为精确未覆盖范围交给现有 Gap
证据流程处理，不会被自动吞掉。

### 6.15 自动分类候选的 VAD 证据边界

**[已实现并验证评测边界；分类决策待私有样本验证]**

Worker 现在可以通过 `analyze-speech-activity` 对当前仍为 `unresolved` 的
范围运行 revision-pinned `pyannote/segmentation` VAD 候选。模型必须绑定
完整的 40 位 commit SHA，证据同时记录 pyannote 版本和固定配置，并锚定：

- 当前 Gap 报告 generation 和 payload SHA-256；
- 当前整篇对齐报告 generation 和 payload SHA-256；
- 标准化音频 SHA-256、采样率和精确时间范围。

检测返回的语音区间必须有限、有序、不重叠、非空且不越过标准化音频。资源
不足会在模型调用前安全暂停，任何区间异常或模型错误都不会留下半份检测
报告。

本阶段只保存 `speech_detected` 或 `no_speech_detected` 的时间证据。报告和
每一个范围都明确保存 `materialization_authorized = false`，不会新增稳定
`non_speech` 或 `inaudible` 段，也不会改变作业状态。VAD 无语音结果不能单独
证明“非语音”，更不能区分“听不清”；自动落盘仍必须等待代表性私有标注样本
的误检、漏检评测和决策阈值批准。

### 6.16 私有 VAD 金标准评测与指标门

**[已实现并验证评测工具；真实基线仍待私有样本和模型]**

新增独立的 `speech-capture-vad-probe`，可以读取 Git 已忽略目录中的私有
manifest。每个样本只使用不透明 ID、相对音频路径，以及有序、不重叠的
`speech` / `non_speech` 毫秒范围；未标注时间不参与指标。

评测工具会在内存中把音频标准化为 16 kHz 单声道 PCM，并拒绝：

- 路径逃逸或符号链接音频；
- 评测期间变化的源文件；
- 超长、无法解码或空音频；
- 重叠、越界或类型未知的标注；
- 非法 VAD 检测区间；
- 只提供一部分验收策略参数。

报告按标注时长计算语音召回率、语音漏检率、非语音特异度、非语音误报率和
四类混淆时长，同时统计出现漏检或误报的样本数。报告只含不透明 ID、源文件
SHA-256 和指标，不含路径、文件名、文字稿或凭据，并以 `0600` 权限原子
写入。

项目没有内置拍脑袋阈值。只有项目所有者同时提供两项比率上限和两项最小
标注时长后，工具才给出 pass/fail；即使通过，
`automatic_materialization_authorized` 仍固定为 `false`。

## 8. 已经设计、但尚未写成代码的部分

### 8.1 输出产物包

**[基础产物已实现；纯净 Note、证据版拆分与时间线摘要待开发]**

Worker 内部证据与用户侧 Markdown 必须分开。计划生成：

1. `transcript.raw.json`
   - 保存原始模型证据；
   - 包含模型、块、尝试、时间范围、校验和等；
   - 不能因为后来纠正文字而被覆盖。

2. `transcript.md`
   - 面向人阅读的完整文字稿；
   - 带稳定段 ID、时间范围、说话人和不确定标记；
   - 可以从文本跳回音频证据。

3. `timeline.md`
   - 基于完整校订逐字稿，按录音先后顺序生成内容地图；
   - 按语义转折划分时间段，不机械固定每五分钟，通常每段约 3–8 分钟；
   - 每段只回答“这段时间讲了什么”，不套会议、访谈、演讲或个人备忘模板；
   - 覆盖整段录音的全部有效内容，同一话题后面再次出现时仍保留在后面的时间位置；
   - 使用纯净时间标题、简述和信息点，不插入逐字稿证据链接；
   - 听不清范围如实标注，不根据上下文猜测补写。

4. `speech-record.json`
   - 面向未来 Agent 的稳定机器可读记录；
   - 包含源文件事实、内容类型、说话人、时间线、提炼结果、证据链接、质量状态和修订信息。

5. `note.md`
   - 面向 Obsidian 默认阅读的纯净最终笔记；
   - 根据会议、访谈、课程、语音备忘等类型使用不同结构；
   - 不显示逐字稿链接、“依据”、章节导航、speech ID 或录音技术信息；
   - partial 状态只保留一句不带链接的普通文字提醒；
   - 保护 `我的补充` 等用户区域，重新生成不得覆盖。

6. `note.evidence.md`
   - 内容结论与 `note.md` 来自同一份 `speech-record.json`，不得再次调用模型独立生成；
   - 保留当前验收稿中的逐字稿链接、依据、章节导航和质量信息；
   - 作为机器维护的核验稿，不承载用户手工补充。

7. 质量与校验信息
   - 处理是否完整；
   - 哪些范围听不清、非语音或失败；
   - 哪些结论证据不足；
   - 各产物的版本和校验和。

最终面向用户的是四份 Markdown：`note.md`、`timeline.md`、`transcript.md`、
`note.evidence.md`。`transcript.raw.json`、`speech-record.json` 和
`artifact-manifest.json` 属于 Worker 内部证据，默认不进入普通 Obsidian 笔记列表。

### 8.2 结构化笔记原则

**[设计已确定，待开发]**

## 13. 不应在后续开发中被破坏的原则

1. 原始音频永不被修改。
2. 所有可解码时间范围都必须有明确结果，不能静默遗漏。
3. 原始证据先于总结落盘。
4. 会议和访谈必须支持说话人区分。
5. 说话人识别失败不能使文字稿消失。
6. 自动总结的重要结论必须能追溯到文字证据。
7. 本地模型优先，云端默认关闭。
8. Worker 不依赖 Google Drive 或其他特定同步产品。
9. Obsidian 关闭或外出笔记本断网时，家中 Worker 可以继续任务。
10. `processed` 不等于 `published`。
11. 发布必须是可校验、可恢复的原子过程。
12. 磁盘和内存危险时要提示和安全暂停，不自动清理用户文件。
13. 同一 Worker 同时只运行一个重型任务。
14. 用户手写内容不能被重新生成覆盖。
15. 普通重启不应要求重新配对。
16. 私人音频、文字、凭据、数据库、绝对路径和原始报告不能进入 Git。
17. Obsidian 页面必须先设计、生成关键交互图并经用户批准，再开始开发。
18. 首版先服务个人使用，访谈意图识别属于后续扩展。
19. 项目许可证保持 PolyForm Noncommercial 1.0.0，除非用户明确决定更换。
