# Stage H · Speech Capture 交互设计基线 V1

状态：已由项目所有者于 2026-08-03 批准，构成 Stage I 的交互实现合同。

## 1. Reading Capture 研究结论

本轮只读研究了本机 Reading Capture 项目的匿名界面截图、已批准的 Creation Workbench 基线、
交互规范和实际样式。没有打开真实 Vault，也没有读取用户笔记。

Speech Capture 应复用的是体验语言，不是业务页面本身：

- 使用稳定的工作区骨架。页头、当前对象、导航和主工作区位置保持不变，长内容在自己的区域滚动；
- 每个页面只有一个明确的下一步主动作。按钮直接写明后果，状态标签不能长得像按钮；
- 绿色表示就绪、有效、通过或推荐主动作；蓝色表示正在处理或当前候选；琥珀色表示需要注意、
  等待决定或可恢复例外；红色表示失败、阻断或破坏性后果；灰色表示次要、历史或不可用；
- 颜色不是唯一信号，同时使用文字、图标和位置；
- 深色基线采用墨绿黑背景、低对比边框、8–10px 圆角、轻量阴影，避免大面积装饰渐变；
- 工作台界面使用紧凑无衬线字体；长篇逐字稿和 Note 阅读区可使用中文衬线字体、较宽行距；
- 主控件在内容滚动时仍可见；列表与详情、正文与侧栏分别滚动；
- AI 结果、用户修订、自动通过和人工确认必须保持不同语义，任何重生成都不能静默覆盖旧版本；
- 窄窗口将次要面板移动到正文下方，不产生水平滚动；键盘焦点顺序与视觉顺序一致。

## 2. 产品信息架构

### 2.1 一级入口

Obsidian Ribbon 和命令面板提供一个主要入口：`语音工作台`。

`语音工作台` 是插件首页和统一外壳，不是一个需要单独返回的中转页。打开入口后默认显示左侧
任务列表、中间单页 `新建语音任务` 和右侧提交前确认；选择已有任务时，同一外壳的中间与右侧
切换为该任务的进度或复核内容。

工作台内部包含三个用户可理解的区域：

1. `任务`：提交音频、查看队列、进度、警告、恢复和发布；
2. `逐字稿与复核`：播放证据、阅读校订稿、处理说话人和文字修订；
3. `Worker 与设置`：连接、配对、默认模式、输出位置、隐私和诊断。

`note.md`、`timeline.md` 和最终 `transcript.md` 仍作为普通 Obsidian 文件打开。工作台不重新
制造一个与 Vault 笔记竞争的阅读器；只有证据定位、说话人识别结果和修订需要专用复核界面。
这一边界已确认：Stage I 不另做纯净 Note 阅读器。

### 2.2 桌面工作台骨架

```text
页头：语音工作台 | Worker 健康状态 | 新建语音任务
任务栏 240px | 当前任务主工作区 minmax(0, 1fr) | 情境侧栏 300–340px
```

- 任务栏显示全部任务及明确状态，选择整张任务卡即可切换，不增加同义“查看”按钮；
- 主工作区始终先显示当前阶段和下一步，再显示进度、内容或问题；
- 情境侧栏只显示当前任务需要的资源、连接、文件和操作，不重复主区信息；
- `语音工作台` 指整个插件的任务提交、进度和复核外壳，不是一个需要从复核页返回的额外页面。
  因为逐字稿复核仍保留任务栏，顶部不再显示 `返回语音工作台`；切换任务直接使用左栏，打开
  Note 或时间线使用当前任务的明确动作；
- 左、右两栏各自提供始终可发现的收起/展开控件，并且彼此独立：收起左栏后显示“主区 + 右栏”，
  收起右栏后显示“左栏 + 主区”，两栏同时收起时由主区占满可用宽度；
- 首次使用时左右两栏默认展开；此后按本机界面状态记住用户上一次选择，重新打开工作台时恢复，
  不把该偏好写入音频任务、笔记或 Vault 同步数据；
- 展开状态下，收起图标放在各自栏目的标题行内：左栏位于 `任务` 标题右侧，右栏位于
  `当前片段` 标题左侧。图标本身使用 16px 细线箭头和至少 32×32px 的透明点击区域；默认无
  方形外框、无蓝色描边，只在悬停时出现低对比底色，在键盘聚焦时显示可访问的焦点环；
- 栏目收起后只在对应分隔线留下 20–24px 宽的窄边缘把手，用朝向内容区的箭头恢复栏目，不使用
  漂浮的蓝框方形按钮；展开/收起只改变布局，不重置当前任务、选中段落、播放位置、表单或
  滚动上下文；
- 低于约 1180px 时情境侧栏移到主区下方；低于约 860px 时任务栏收为顶部任务选择器。
  响应式临时折叠不覆盖用户记住的桌面偏好，窗口恢复后回到用户此前选择的栏目状态。

## 3. 新建语音任务

新建任务已确认采用单页表单，不拆成分步向导。首屏只要求用户确认完成提交所必需的信息：

1. 音频文件：拖放或选择，显示文件名、格式、大小和时长；
2. 录音日期：显示建议来源，允许确认、修改或暂时未定；
3. 补充背景：可选的自由文本，多行多段，不限制格式；说明文字固定为
   `仅供逐字稿校订和笔记提炼参考，不会替代录音证据。`；
4. 处理位置：显示已配置或实际检测到的 Worker；个人 V1 默认选择已就绪的家中远程 Worker，
   本机 Worker 作为可选能力；本机/远程以普通名称和连接状态显示；
5. 处理模式：默认 `准确优先`，可选 `速度优先`；模型 ID 收入高级信息；
6. 内容类型：默认 `自动判断`，必要时允许用户覆盖，但不要求预先选择；
7. 主动作：`确认并开始上传`。

高级项折叠显示语言提示、输出 Vault 和源文件保留策略。不能把模型、端口、哈希或协议字段放在
默认路径中。

### 3.1 本机与远程 Worker 选择

本机和远程不是两套处理架构：本机通过 loopback 调用同一套 Worker API，远程通过已配对的私有
HTTPS 地址调用；一个 Vault 可以配置多个 Worker，但每个新任务只绑定一个处理 Worker。

- 个人 V1 首次默认选择已配对且就绪的家中 Worker；记住用户最后一次成功使用的 Worker，但如果
  它当前不可用，不能自动把任务交给另一个 Worker；
- `这台 Mac` 只有在本机 `/v1/health`、能力协商、配对和必要就绪检查全部通过后才是可选择的
  `已就绪` 状态；
- 本机端点连接失败时不能断言 `未安装`，因为前端无法仅凭失败区分尚未安装、服务未启动、端口
  改变或本机安全软件阻止。统一显示 `这台 Mac · 未检测到可用 Worker`，该项不可选择；
- 点击不可用的本机项只展开说明：`可能尚未安装，或 Worker 服务没有启动。`，提供次要动作
  `重新检测` 和 `查看安装与启动说明`；不得自动安装、自动启动或静默切换到远程 Worker；
- Worker 可达但当前 Vault 尚未配对时显示 `需要配对`，进入短码配对流程；
- Worker 可达但协议或必要能力不兼容时显示 `版本不兼容`，阻止上传并明确要求更新插件或 Worker；
- Worker 已连接但模型、磁盘或运行环境尚未就绪时显示 `已连接 · 尚未就绪`，主提交按钮禁用并
  引导在 Worker Manager 中完成对应动作；
- 选择处理位置发生在上传之前。上传开始后切换 Worker 必须创建新的关联尝试，不能把正在上传或
  处理的任务静默迁移。

现有核心已实现 health、能力协商、配对和任务资源预检；但“未安装/未启动”的精确区分，以及模型
和服务的提交前就绪状态目前只存在于 Worker Manager 状态采集，不在插件可读 API 中。进入前端
编码前需要决定并补齐一个不含私人内容的 Worker/Manager 就绪状态契约，否则界面只能诚实显示
`未检测到可用 Worker`，不能显示更具体结论。

### 3.2 首次配对与长期管理

首次连接继续发生在 `语音工作台` 内，不打开独立向导或要求用户理解服务端术语：

- 可达但尚未授权的 Worker 显示 `已发现 · 尚未配对`；不可达的本机候选仍显示
  `未检测到可用 Worker`，两者不能混为一种状态；
- 配对页一次展示设备确认、短时配对码和 Vault 授权范围。配对码由目标 Mac 的 Worker Manager
  生成，过期后只能重新生成；插件不能自行显示、恢复或记录旧配对码；
- 授权默认只覆盖当前 Vault。成功返回的长期凭据必须存入当前设备的系统钥匙串，不能进入 Vault、
  插件设置文件、日志、诊断包或截图，也不能在设置页提供显示/复制功能；
- 配对成功后立即显示 Worker、私有网络、兼容性和当前 Vault 授权的用户可理解结论，并允许把该
  Worker 设为新任务默认处理设备；不再显示配对码；
- 设置页允许重新检测状态、更改 Vault 授权和撤销当前设备授权。撤销是低频破坏性动作，需要二次
  确认；撤销后立即停止访问，但不删除 Worker 已保存的任务或 Vault 已发布文件；
- 普通 Worker 重启、系统重启和插件重开都不要求重新配对。只有用户主动撤销、凭据轮换失效或
  安全状态不再可信时才重新进入配对；
- 设置页不显示 IP、端口、token、模型 ID 或本地路径。高级连接诊断另行展开，并继续遵守内容无关
  的诊断边界。

## 4. 本地与远程完整流程

### 4.1 本机 Worker

```text
选择音频 → 确认日期/背景 → Worker 预检 → 上传/本地接收 → 媒体验证 → 排队
→ 转写 → 时间对齐 → 说话人识别 → 笔记提炼 → 质量检查 → 已处理
→ 发布到 Vault → 打开纯净 Note
```

### 4.2 远程 Worker

```text
选择音频 → 确认远程 Worker 在线 → 可恢复分块上传 → Worker 确认完整接收
→ 客户端可以关闭 → 家中 Worker 继续处理 → 重新连接并恢复快照
→ 已处理但待发布 → 当前设备或其他获授权设备领取发布 → 原子写入 Vault
```

上传完成前明确显示“关闭本机将暂停上传”；Worker 已确认接收后改为“现在可以关闭 Obsidian，
处理会继续”。不能在只上传了部分分块时给出后者。

## 5. 任务工作台

### 5.1 进度表达

顶部使用阶段轨道，但不把不同耗时阶段假装成等比例进度：

- `上传`、`验证`、`排队`、`转写`、`对齐`、`说话人`、`提炼`、`质量检查`、`发布`；
- 已完成为绿色勾选；当前阶段为蓝色并显示名称、已处理时长和可靠时才显示预计剩余；
- 等待决定为琥珀；失败/阻断为红色；未开始为灰色；
- 总体百分比仅在 Worker 提供有意义的阶段进度时显示，不拼接虚假的跨阶段百分比。

### 5.2 渐进逐字稿

- 已提交稳定段使用普通正文；
- 当前尾部明确标为 `临时结果`，使用蓝色左边线和较低对比背景；
- `跟随最新内容` 是显式开关。用户向上滚动后自动停止跟随，但不停止任务；
- 说话人尚未完成时显示 `说话人识别中`，而不是隐藏匿名标签；
- 重连后用快照和游标恢复，界面显示一次 `已恢复到最新进度`，不重复插入文字段；
- 预览不冒充最终证据稿，页脚固定说明 `处理完成后将生成完整校订逐字稿。`。

## 6. 逐字稿与证据复核

```text
顶部：任务标题、处理完整度、打开 Note、重新生成笔记
音频条：播放/暂停、当前时间、总时长、波形概览、上一/下一证据
左侧主区：按时间顺序的逐字稿段
右侧情境栏：当前段文字、说话人、原始证据状态、保存修订
```

- 点击逐字稿段会定位音频；从 `note.evidence.md` 进入时自动选择对应段；
- 说话人先显示匿名标签，可批量改显示名，例如把全部 `说话人 2` 显示为 `王总`；这只改变
  人物标签的显示名称，不改变哪些段落属于该人物；
- 当自动识别把某一句分给了错误的人时，在当前选中段落的修订区提供 `这段话是谁说的？`，
  辅助说明固定为 `只纠正当前这一段，不会影响其他段落。`；这里不能使用两个固定人物按钮，
  必须使用能够覆盖本次录音全部已识别人员的选择器；
- 选择器默认显示当前说话人。展开后以多行清单列出全部已识别人员，同时显示人物名称和仍有
  区分价值时的匿名标识，例如 `王总 · 说话人 2`；五六人及更多人数下允许内部滚动，并提供
  按显示名或匿名标识搜索，不挤压逐字稿主区；清单末尾固定提供 `暂不确定`；
- 单段说话人选择不会点击后立刻写入，而是与当前段的文字修订一起通过 `保存此段修订` 确认。
  保存后只更新当前段的说话人标识，不批量改名，也不改变同一说话人的其他段落；
- 文字修订显示当前校订文字，不直接改写原始 ASR；保存前说明影响范围；
- `重新生成笔记` 只在修订会影响总结时出现推荐状态，进入前后差异页；
- 差异页并排显示旧版和新版机器生成区域，`我的补充` 单独显示为受保护且未改动；
- 用户确认后才把新版设为当前版本，旧版本和修订记录继续可追踪。

### 6.1 音频播放的真实能力边界

当前 Worker 已具备的基础：

- 完整上传后在 Worker 私有目录保留经过大小、SHA-256 和可解码性校验的源音频副本；
- 每个稳定逐字稿段包含 `segment_id`、`start_ms` 和 `end_ms`，足以把当前段、上一段和下一段
  映射到音频时间范围；
- 本机与远程客户端共享按设备和 Vault 授权的 Worker API，远程连接使用私有 HTTPS 网络。

Stage H 批准后已补齐的后端能力：

- 标准化阶段确定性生成 8 kHz、8-bit、单声道私有复核 WAV，和逐字稿时间轴误差不超过 1 毫秒；
- 面向已配对设备提供鉴权、Vault 授权的复核音频 metadata 和 HTTP byte-range 内容接口；
- 复核音频不进入 Markdown/JSON 发布包，当前按 Worker job lifetime 保留；
- 新增鉴权且内容无关的 readiness 快照，区分服务可达与资源/运行时/模型真正可启动。

V1 交互按以下来源优先级设计，但在对应后端能力完成前必须标为设计依赖：

1. 当前设备仍能访问与任务 SHA-256 一致的本地源音频时，直接本地播放；
2. 本地源不可用、家中 Worker 在线时，通过已配对的私有 HTTPS 连接流式读取 Worker 生成的
   低码率复核音频，不默认下载完整原始音频；
3. 家中 Worker 离线或复核音频已超过保留期时，逐字稿仍可阅读和修改，但播放控件禁用并明确
   显示原因，不回退到公开网络或第三方云端；
4. 需要长期保留音频复核能力时，由用户明确启用归档源音频，不能因为界面有播放按钮就静默改变
   默认保留策略。

个人 MVP 继续使用普通时间滑杆，并显示 `家庭 Mac 在线 · 流式播放`。Worker 离线由连接状态明确
禁用播放，复核音频不存在或校验失败时由稳定错误码显示不可用，文字复核不受影响。可选波形峰值、
显式过期策略和多客户端带宽控制属于后续运营优化；job 删除/过期实现必须同时安全删除复核音频，
不能留下脱离任务生命周期的副本。

### 6.2 总结差异与版本记录（V1 已确认）

- 从逐字稿修订触发重新生成后，先进入总结差异页，不直接替换当前 `note.md`；差异只比较机器
  生成区域，受保护的 `我的补充` 作为单一当前区域继续保留，不参与机器版本回滚；
- V1 只提供整版选择，不提供逐条勾选、逐段合并或手工拼装两版：`接受新版笔记` 将候选版设为
  当前 Note；旧版和本次差异进入版本记录；
- `不采用新版` 保持旧版为当前 Note，候选版以“未采用”状态进入版本记录，不被静默删除；按钮
  附近必须明确说明这一后果，避免用户把它理解为永久删除；
- `继续修改逐字稿` 返回证据复核，并保持当前 Note 不变，不自动选择任一候选版本；
- 版本记录在 V1 只读：可以查看历史版本和与当前版本比较，但不提供一键回滚、逐条合并或删除；
  这些能力留到真实使用证明有必要后再扩展；
- 窄窗口不把两列差异强行压缩，而按每个变更块纵向显示 `原版本` 后接 `候选版本`，整版动作固定
  在当前变更阅读上下文之后，页面不产生横向滚动。

## 7. 核心状态矩阵

| 用户看到的状态 | 颜色 | 主区说明 | 主动作 | 必须保留的内容 |
| --- | --- | --- | --- | --- |
| 没有任务 | 灰 | 说明支持的来源和处理方式 | 新建语音任务 | 无 |
| Worker 就绪 | 绿 | 本机或远程 Worker 可用 | 开始上传 | Worker 名与模式 |
| 本机 Worker 未检测到 | 灰/琥珀 | 可能未安装或服务未启动，不武断判断原因 | 重新检测/查看说明 | 当前远程选择不变 |
| Worker 需要配对 | 琥珀 | 服务可达，但当前设备/Vault 尚未授权 | 开始配对 | 已保存的非秘密连接信息 |
| Worker 版本不兼容 | 红 | 协议、产物版本或必要能力不兼容 | 查看更新要求 | 不开始上传 |
| Worker 尚未就绪 | 琥珀 | 缺少模型、磁盘或运行环境条件 | 打开 Worker Manager | 不开始上传 |
| 上传中 | 蓝 | 已上传字节、总量、速度、缺失分块 | 暂停上传 | 已上传分块 |
| 校验中 | 蓝 | 正在检查完整性和音频可解码性 | 等待 | 已接收完整文件 |
| 排队中 | 灰/蓝 | 队列位置和前方任务 | 安全暂停 | 完整上传与任务 ID |
| 转写/处理 | 蓝 | 当前阶段、音频时长进度、稳定文字 | 查看逐字稿 | 稳定段和检查点 |
| 需要决定 | 琥珀 | 缺少日期、类型或复核结果 | 处理问题 | 已完成阶段 |
| 内存警告 | 琥珀 | 可能变慢但仍安全 | 继续观察 | 已完成块 |
| 磁盘阻断 | 红 | 可用空间、预计需要和安全保留 | 更换位置或释放空间后重试 | 上传/证据不删除 |
| 安全暂停 | 琥珀 | 在块边界暂停且无内容丢失 | 恢复或切换速度模式 | 所有检查点 |
| Worker 离线 | 琥珀 | 区分上传前、上传中和已接收后的影响 | 自动重试；失败后手动重试 | 本地游标与已知快照 |
| 已恢复 | 绿/蓝 | 恢复到最新 revision 和阶段 | 继续查看 | 不重复稳定段 |
| 部分完成 | 琥珀 | 精确说明仍有听不清/失败范围 | 复核或接受部分结果 | 全部已知证据 |
| 处理失败 | 红 | 用户语言原因和可恢复边界 | 重试当前阶段 | 已成功子阶段 |
| 已处理未发布 | 绿+琥珀 | 产物已安全保存在 Worker，Vault 尚无最终包 | 等待已授权客户端自动发布 | 完整产物包 |
| 发布冲突 | 琥珀 | 目标目录已有用户修改或同步差异 | 查看差异 | 两侧内容均不覆盖 |
| 已发布 | 绿 | Vault 包已写入并验证 | 打开 Note | 发布回执与 Worker 产物 |

### 7.1 恢复与发布状态的动作规则

- 磁盘阻断发生在处理途中时，任务只在安全块边界暂停；页面必须同时说明所需空间、当前空间、
  安全保留规则和已经保存的内容。界面只能查看 Worker 自有占用和重新检测，不能提供删除无关文件
  的动作；
- 上传已经完成后连接中断，客户端只能显示最后已知进度和 `Worker 状态暂时未知`，不能把断线等同
  于 Worker 失败或任务暂停；最后快照继续可读，临时尾部停止更新；
- 连接中断后客户端每隔 1 分钟自动重试，最多 3 次，并显示当前次数和下次重试时间；三次均失败后
  停止后台重试，并在 Obsidian 语音工作台的主区显示唯一主动作 `重新连接书房 Mac`。用户不需要
  前往 Worker Manager 或其他应用执行重试；点击后立即尝试一次，若仍失败则保留当前页面、最后
  快照和再次重试入口。页面不提供 `稍后再试`；
- 重连成功后从快照和事件游标恢复，稳定段按 ID 去重。短暂显示 `已恢复到最新进度`、同步段数和
  无重复/无修订丢失结论，随后回到普通处理中状态；
- `已处理` 与 `已发布` 继续分开。已授权客户端在线且目标没有变化时自动发布；若处理完成时没有
  可用的已授权客户端，待发布页说明产物安全位于 Worker、尚未进入当前 Vault，并列出用户可理解
  的四类产物，不用技术文件名主导页面；客户端恢复后自动继续发布；
- 发布时发现目标内容变化，现有 Vault 内容和 Worker 产物均保持原样。V1 不提供默认一键覆盖；
  第一动作必须是 `查看差异`；用户看完差异后才能选择 `保存到新位置`，不能在冲突首屏直接把
  保存到新位置作为默认动作；
- 冲突页不提供 `保留当前版本，稍后处理` 或同义按钮，因为当前 Vault 文件和 Worker 待发布产物
  本来就会持久保留，不需要一次额外的“保留”操作。用户切换任务或关闭页面时，任务继续显示为
  `发布冲突`；以后从左侧任务列表选择同一任务即可回到冲突说明或差异页面。

## 8. Worker 数据到界面的映射

| 界面元素 | Worker/API 来源 | 显示规则 |
| --- | --- | --- |
| Worker 健康 | health + capabilities + authenticated readiness | 只显示用户可行动的结论，不显示本地路径 |
| Worker 候选列表 | 配置记录 + 本机 health 探测 + 配对状态 | 不硬编码本机可用；个人 V1 优先家中已就绪 Worker |
| 当前任务状态 | job snapshot `status` / `stage` / `revision` | 每个 revision 只应用一次 |
| 上传进度 | upload parts、received bytes、missing parts | 断线后按服务端清单重建 |
| 音频处理进度 | processed duration / total duration | 使用时间和阶段，不伪造总体 ETA |
| 复核音频 | 本地同源文件或 Worker review-audio metadata/range | 始终显示来源；Worker 离线或不可用时禁用播放但保留文字复核 |
| 稳定文字 | snapshot transcript segments | 按稳定 ID 去重，不因说话人更新重建正文 |
| 临时尾部 | provisional transcript + revision | 始终带 `临时结果` 标签 |
| 说话人状态 | diarization status + speaker labels | unavailable 时保留文字并提示复核 |
| 资源警告 | preflight / Manager issue codes | 稳定 code 映射为本地化文案和行动 |
| 连接恢复 | update cursor + snapshot revision | 游标失效时完整拉取快照 |
| 已处理 | artifact package and manifest verification | 与 published 分开呈现 |
| 发布 | lease / receipt / conflict result | 只在完整校验后显示成功 |
| 修订 | corrections + job revision | 保存前验证当前 revision |
| 总结差异 | summary revisions | 只展示机器生成区域变化 |

## 9. 视觉与组件约束

### 9.1 暗色基线

- 页面背景：`#070907` 到 `#0c100d` 的极轻墨绿变化；
- 面板：`#0d120e`；卡片：`#111711`；边框：`#2a332a`；
- 主文字：`#e6e4dc`；正文：`#d1d6ce`；次要文字：`#969f95`；
- 绿色：`#62c95d`；蓝色：`#4c78ff`；琥珀：`#f6a044`；红色：`#e05b5b`；
- 8–10px 圆角，主按钮最小高度 36–40px，可能触屏的目标最小 44px；
- 常规间距使用 4/8/12/16/24/32px 系列；面板内边距通常 16–20px。

### 9.2 排版

- 工作台：Obsidian 界面字体/PingFang SC，正文 13–14px，状态 11–12px，页面标题 28–30px；
- 长篇阅读：Songti SC/Noto Serif SC，正文 17–18px，行高 1.68–1.75，内容宽度不超过 920px；
- 数字进度使用等宽数字；英文 kicker 只用于视图身份，不承担主要中文信息。

### 9.3 浅色主题

保留相同空间、层级和语义色；将背景与面板切换为暖灰白和淡鼠尾草色。浅色稿不能只做反相，
文字对比度至少 4.5:1，蓝/绿/琥珀状态仍需同时有标签与图标。

V1 不在语音工作台或插件设置中提供独立的深色/浅色切换，也不提供自定义配色。界面始终跟随
Obsidian 当前主题；Obsidian 在工作台打开期间切换主题时，组件立即切换对应 token，但当前任务、
表单输入、选中段、滚动位置、音频位置和未保存修订均不重置。插件独立主题覆盖与自定义颜色属于
功能流程跑通后的后续优化。

### 9.4 栏目收起与窄窗口候选

- 桌面宽度下分别覆盖“只收起左栏”“只收起右栏”和“左右同时收起”。每个被收起的栏目只留下
  22px 左右的边缘恢复把手；主区流式占用腾出的宽度，字号、任务状态和当前选择不改变；
- 只收起左栏时，右侧当前片段修订区继续可用；只收起右栏时，左侧任务切换继续可用；两栏同时
  收起时逐字稿成为唯一视觉主体，但当前修订草稿、说话人选择和播放位置仍保存在界面状态中；
- 窄窗口不把三栏同比缩小。任务栏改为顶部 `当前任务` 选择器；选中逐字稿段后，右侧当前片段区
  改为在该段正下方就地展开，而不是移动到整份逐字稿末尾。音频控件允许分两行，筛选标签可以在
  自身区域横向滚动，正文和页面本身不产生横向滚动；
- 窄窗口触发的是响应式临时布局，不改写用户记住的桌面栏目状态。窗口恢复后回到之前的桌面栏
  组合；
- `已记住左栏/右栏/左右栏收起状态` 只作为操作后的短暂低干扰反馈，约 2 秒后消失，不常驻占用
  主区；若右侧当前片段中存在未保存修订，右边缘恢复把手显示一个小琥珀点，草稿继续原样保留，
  但不阻止用户收起栏目；
- 浅色候选使用暖灰白、淡鼠尾草和深炭绿色文字，不做机械反相；不可用 Worker、处理中、警告和
  主动作继续同时依赖文字、图标与语义色。

## 10. 无障碍与动效

- 所有交互元素有可见焦点；Tab 顺序遵循页头→任务→主区→情境栏→主动作；
- 状态变化通过 `aria-live=polite` 合并播报，不逐字朗读每个增量段；
- 进度动画只使用低幅度脉冲或条形变化；减少动态效果时关闭脉冲和自动平滑滚动；
- 颜色、位置和图标不能单独承担含义；
- 破坏性取消必须显示会保留什么、会停止什么，再要求确认。

最终简体中文文案与消息键见
[`message-catalog-v1.md`](message-catalog-v1.md)；键盘、屏幕阅读器、响应式、减少动态效果和设计
批准状态见 [`accessibility-approval-checklist-v1.md`](accessibility-approval-checklist-v1.md)。

## 11. 首批视觉稿范围

首轮先生成并讨论最核心的四张桌面暗色稿：

1. 新建语音任务：文件、日期、补充背景、Worker 和处理模式；
2. 正在处理：阶段轨道、稳定文字、临时尾部、说话人状态和资源侧栏；
3. 逐字稿复核：音频证据、说话人改名/归属和文字修订；
4. 修订后重新生成：新版/旧版差异及受保护的 `我的补充`。

第二轮在首轮视觉方向确认后补充资源阻断、离线恢复、已处理未发布、首次 Worker 设置、浅色主题
和窄侧栏，避免在基础布局未确认前一次生成大量相互矛盾的稿件。

## 12. 项目所有者确认状态

### 12.1 已确认

- 整体视觉延续 Reading Capture 的暗色墨绿语言、状态颜色和紧凑密度；
- `语音工作台` 作为插件首页和统一工作外壳，默认显示任务列表、单页新建任务和提交前确认；
- 使用左、中、右三栏工作台，但左右栏必须能够独立收起、同时收起，并记住上一次状态；
- 新建任务在一个页面内完成，不使用多步向导，保持简单简洁；
- 纯净 `note.md` 继续使用 Obsidian 原生阅读，专用界面只处理证据、说话人和修订；
- 逐字稿复核不显示 `返回语音工作台`，任务列表就是同一工作外壳中的导航；
- 单段说话人纠错使用可搜索、可滚动的完整多人清单，并与当前段文字修订一起保存；
- 左右栏的收起动作并入栏目标题行，默认不显示方框，收起后使用窄边缘恢复把手；
- V1 音频复核遵循“当前设备同源文件优先、家庭 Worker 私有流式播放其次、Worker 离线时文字
  可读但播放禁用”，并把受认证音频读取契约列为前端编码前必须补齐的后端依赖；
- 处理位置架构同时支持本机和远程 Worker；个人 V1 默认家中 Worker。本机未检测到可用 Worker
  时不可选择，不静默切换，并使用无法误判安装状态的响应文案。
- 磁盘不足页的原因、保留边界和操作说明已确认清楚；
- 连接中断后每隔 1 分钟自动重试、最多 3 次，失败后才提示手动重试，不提供 `稍后再试`；
- 正常情况自动发布；发布冲突先查看差异，查看后才能选择保存到新位置。
- V1 只跟随 Obsidian 当前深色/浅色主题，不设计插件内主题开关或自定义配色；主题变化不重置任何
  任务或修订状态。
- 首次 Worker 设置使用工作台内的单页连接方式；配对成功后长期凭据进入系统钥匙串，普通重启
  不重新配对，设置页只提供状态检查、Vault 授权调整和显式撤销。
- MVP 的总结差异只做整版接受或不采用，不做逐条合并；未采用候选仍可追踪，`我的补充` 不参与
  机器版本切换；版本记录只读，不提供回滚、删除或合并，复杂版本管理推迟到后续版本。
