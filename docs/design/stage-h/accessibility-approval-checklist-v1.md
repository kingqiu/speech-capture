# Stage H · 无障碍与设计批准清单 V1

本清单是进入 Stage I 前的设计验收合同，不是前端测试结果。`已定义` 表示交互要求已经固定；
实际代码完成后仍需逐项手工和自动验证。

## 1. 键盘操作合同

| 项目 | V1 要求 | 状态 |
| --- | --- | --- |
| 全程键盘可达 | 新建、任务切换、上传、暂停/恢复、复核、修订、发布冲突处理均不依赖鼠标 | 已定义 |
| Tab 顺序 | 页头 → 左栏/任务选择器 → 主区 → 右栏/就地修订 → 主动作 | 已定义 |
| 可见焦点 | 所有按钮、链接、输入框、标签页、下拉框和边缘恢复把手必须有明显焦点环 | 已定义 |
| 栏目收起 | 左/右栏标题按钮可用 Enter/Space；收起后焦点移到对应边缘恢复把手 | 已定义 |
| 多人清单 | 上下键移动，Enter 选择，Esc 关闭并回到触发器；搜索框不吞掉标准编辑快捷键 | 已定义 |
| 逐字稿段 | 每段可聚焦；Enter 选中并定位音频；不把整段正文拆成大量无意义 Tab 停靠点 | 已定义 |
| 音频控制 | Space 仅在播放器具有上下文焦点时播放/暂停；左右键小步 seek，不能覆盖 Obsidian 全局输入 | 已定义 |
| 对话与弹层 | 打开后焦点进入标题或第一项；Esc 关闭；关闭后回到原触发器 | 已定义 |
| 窄窗就地修订 | 展开后焦点进入修订标题；保存/收起后回到所选逐字稿段 | 已定义 |

## 2. 屏幕阅读器与状态播报

| 项目 | V1 要求 | 状态 |
| --- | --- | --- |
| 页面身份 | 每个工作台主视图有唯一一级标题，栏目使用有名称的区域 | 已定义 |
| 状态不靠颜色 | 状态同时有文字；重要警告同时使用图标和说明 | 已定义 |
| 增量逐字稿 | 新稳定段合并后使用 `aria-live="polite"` 低频播报，不逐字朗读临时尾部 | 已定义 |
| 进度 | 上传和处理进度暴露当前值与总值；视觉更新频繁时限制播报频率 | 已定义 |
| 自动重试 | 播报首次断线、每次重试结果和最终手动入口，不按秒播报倒计时 | 已定义 |
| 恢复 | 只播报一次恢复结果，包括同步片段数和无修订丢失结论 | 已定义 |
| 草稿状态 | 收起修订栏时，琥珀点另有可读名称 `当前片段有未保存的修订` | 已定义 |
| 差异语义 | 删除/新增不能只靠红绿；每个变化有 `原版本`、`候选版本` 文本标签 | 已定义 |
| 错误详情 | 用户文案先说明影响与动作；诊断编号可复制但不成为主要朗读内容 | 已定义 |

## 3. 视觉、主题与动效

| 项目 | V1 要求 | 状态 |
| --- | --- | --- |
| 文字对比 | 普通文字至少 4.5:1；大号文字至少 3:1；不可用文字仍须可辨认 | 待实现验证 |
| 非文字对比 | 焦点环、输入边界、状态图标和图表关键线条至少 3:1 | 待实现验证 |
| 缩放 | Obsidian/系统文字放大到 200% 时不丢功能，不产生正文横向滚动 | 已定义 |
| 深浅主题 | 自动跟随 Obsidian；实时切换不丢任务、输入、选择、滚动、播放位置或草稿 | 已确认 |
| 不仅靠颜色 | 绿/蓝/琥珀/红均配合文字和图标；说话人颜色必须同时显示名称 | 已定义 |
| 减少动态效果 | 遵循 `prefers-reduced-motion`；关闭脉冲、波形装饰动画和自动平滑滚动 | 已定义 |
| 自动滚动 | 仅在用户保持“跟随最新”时发生；用户向上阅读后停止自动追随 | 已定义 |
| 短暂反馈 | `已恢复`、`已保存`、`已记住栏目状态` 至少可感知且不抢焦点 | 已定义 |

## 4. 响应式与输入容错

| 项目 | V1 要求 | 状态 |
| --- | --- | --- |
| 桌面三栏 | 左右栏可独立或同时收起，主区使用释放的空间 | 已确认 |
| 窄窗口 | 任务改为顶部选择器，当前段修订就地展开，页面不横向滚动 | 已定义，待视觉最终确认 |
| 状态保留 | 响应式布局不覆盖记住的桌面栏目状态 | 已定义 |
| 点击目标 | 常用目标至少 36×36px；边缘恢复把手视觉可窄，但可交互区域至少 24×44px | 已定义 |
| 输入草稿 | 收起、换主题、断线和响应式切换都不能清空未保存修订 | 已定义 |
| 表单错误 | 错误紧邻字段、有文字说明；提交失败后焦点移动到错误摘要或首个错误 | 已定义 |
| 长文本 | 背景说明、逐字稿、Note 差异和人物名称支持换行，不以省略号隐藏关键后果 | 已定义 |

## 5. 安全与恢复动作

| 场景 | 必须通过的行为 | 状态 |
| --- | --- | --- |
| Worker 断线 | 每分钟自动重试，最多三次；随后 Obsidian 主区出现明确手动重连按钮 | 已确认 |
| 磁盘不足 | 说明需要/可用/安全保留空间和已保存内容；不提供删除无关文件动作 | 已确认 |
| 部分完成 | 可阅读已有结果，明确标出仍需复核范围，不误报为完整成功 | 已定义 |
| 音频不可用 | 禁用播放器并说明原因；文字复核和修订继续可用 | 已确认 |
| 发布冲突 | 先查看差异；之后只能明确保存到新位置，不覆盖现有 Vault 内容 | 已确认 |
| 总结重生成 | MVP 只做整版接受/不采用；`我的补充` 受保护；历史只读 | 已确认 |
| 取消 | 显示会停止什么、会保留什么；破坏性取消必须再次确认 | 已定义 |
| 未知错误 | 保留已完成阶段，提供重试当前阶段或复制诊断编号，不显示私人路径/内容 | 已定义 |

## 6. Stage H 批准状态

### 6.1 已获项目所有者确认

- 语音工作台首页、三栏统一外壳和原生 Obsidian 纯净 Note；
- 单页新建任务、自由文本补充背景、本机/远程 Worker 选择边界；
- 多人说话人显示名与单段归属纠错分离，原始 ASR 不改写；
- 音频来源优先级、离线文字可用、连接重试和恢复；
- 磁盘阻断、自动发布和差异优先的发布冲突；
- 自动跟随 Obsidian 主题，不在 MVP 增加插件主题设置；
- 简化的整版总结选择和只读版本记录。

### 6.2 最终批准

项目所有者于 2026-08-03 明确回复 `确认 Stage H`。以下收尾项随 Stage H 一并通过：

- 首次 Worker 配对页与配对后设置页的信息优先级；
- 栏目收起组合、窄窗口就地修订密度和边缘恢复把手；
- 消息目录中的核心中文术语与主按钮后果文案；
- 本清单作为 Stage I 的设计验收合同。

### 6.3 不得在 Stage I 临时改变

- 证据、原始 ASR、校订稿和 Note 的数据所有权边界；
- 本机与远程 Worker 的选择和静默切换规则；
- 连接重试次数、发布冲突顺序、保存位置或覆盖策略；
- `我的补充` 的保护、总结版本切换语义和私有数据边界；
- 任何破坏性动作的保留/删除后果。

上述项目若发生实质变化，受影响流程必须返回 Stage H 重新评审。

### 6.4 Stage I 视觉还原约束

- 设计图不是灵感参考，而是实现目标。前端必须尽可能 1:1 还原已确认稿的三栏比例、内容层级、
  卡片与边框关系、间距密度、排版尺度、状态颜色、按钮位置、收起把手和窄窗口重排；
- 书面交互基线决定真实行为和数据边界，视觉索引中的当前版本图片决定视觉表现，消息目录决定最终
  中文文案。三者有冲突时不能自行猜测，必须先回到 Stage H 记录核对；
- 每个关键页面完成后都必须在对应窗口宽度和 Obsidian 深/浅主题下生成实现截图，与已确认设计图
  并排核对；明显偏差在该页面完成前修正，不能累积到最后统一美化；
- 不得在编码时自行增加导航层、卡片、按钮、颜色、弹窗、步骤或重新排列信息，也不得为了组件库
  方便而改变用户已经确认的交互；
- Obsidian 原生 API、无障碍或真实内容长度导致无法像素级一致时，允许最小必要适配，但必须保持
  信息层级和操作语义。实质偏差需要记录原因、提供对比截图并再次取得项目所有者确认；
- 图片中的合成示例文字不覆盖 `message-catalog-v1.md`，图片中无法体现的恢复、安全和证据规则不
  覆盖书面合同。
